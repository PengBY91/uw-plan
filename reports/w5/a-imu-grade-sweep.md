# A 硬件前仿真：陀螺等级扫描

**结论（仿真，14 条先导航次，每个等级一次噪声实现）：**

1. **更好的陀螺几乎不改善 VIO 航向本身。** 从仿真假设（g0）到战术级（g4），航向越限时长合计从 827 s 降到 693 s（−16%），最大航向误差中位从 6.6° 降到 6.1°。g1 以上各航次几乎不变：条纹横梁与雾天航次在 g4 下仍有 7–9.5° 的最大误差，而 g4 的冻结零偏预算要 4504 s 才达到 3° 容限，远长于约 150 s 的航次。航向失效来自视觉更新给出的一致但错误的信息，不是陀螺漂移。唯一明显受益的是斜墙（4.4° → 1.2°）。
2. **陀螺等级决定 DET-DIR 航向通道能否工作，但只在冻结零偏下。** 冻结零偏−预算方式下，DET-DIR 航向漏报从 g0 的 89% 降到 g1 的 38%，g4 为 24%，误归因保持在 0–10%。最大的一步在 g0 → g1，也就是 T_tol 从 23 s 增至 134 s、接近航次长度时；之后收益递减。
3. **在线零偏作航向来源时，好陀螺反而更差。** 在线零偏下 DET-DIR 航向漏报从 g0 的 63% 升到 g2–g4 的 96–99%，误归因 22–31%。估计器的在线零偏会吸收视觉造成的航向误差，于是陀螺积分与错误航向一致，冲突消失。陀螺噪声越小，零偏估计越"听"视觉。航向来源应采用冻结零偏，这与先导中的选择一致。
4. **提前退出判据。** 平台 IMU 的 Allan 方差测出后，按同一公式算 T_tol（3σ 达到 3° 航向容限的时长）。T_tol 只有几十秒（g0 量级）时，冻结零偏航向通道基本失效（漏报约 90%），航向只能退回 DET-SCALAR 或外部参考。T_tol 达到航次关键段长度（这里约 130 s 以上）时，航向通道可用。这一阈值依赖航次长度和初始零偏误差，平台上需用真实零偏初值误差重算。

## 1 方法

- **数据**：`scripts/sim_imu_grade.py` 由仿真真值姿态求机体角速度（中心差分），加零偏随机游走 K 与白噪声 N，起点是仿真的真实初始零偏。加速度计不变。重构检查：残差 σ = 0.0020，与仿真 AngVelSigma 一致。种子 = 1000 × 等级号 + 航次序号。
- **等级**（N rad/s/√Hz，K rad/s²/√Hz，T_tol 为解析值，不含初始零偏误差）：

  | 等级 | 含义 | N | K | T_tol（s） |
  | --- | --- | ---: | ---: | ---: |
  | g0 | 仿真假设（对照，新实现） | 1.414e-4 | 2.828e-4 | 23 |
  | g1 | EuRoC ADIS16448（Kalibr 值） | 1.6968e-4 | 1.9393e-5 | 134 |
  | g2 | 工业级 MEMS，ARW 0.3°/√h | 8.7e-5 | 4e-6 | 384 |
  | g3 | 高端 MEMS，ARW 0.1°/√h | 2.9e-5 | 1e-6 | 970 |
  | g4 | 战术级，ARW 0.012°/√h | 3.5e-6 | 1e-7 | 4504 |

- **运行**：`scripts/imu_sweep.sh` 对每个等级、每条航次：生成数据集 → `sim_to_bag` → `uwbench audit` → OpenVINS A0 以 1× 回放 → `eval-traj`。OpenVINS 配置中的陀螺噪声参数随等级改写，即估计器知道正确的噪声。
- **检测**：`detect-a` 两种航向来源，各加 `health_target: 0.05`：冻结零偏−预算（`review_default`）与在线零偏（`review_default_online_yaw`）。阈值按留一航次选取。
- **输入完整性**：70 个运行全部 rc = 0。第一轮有 11 个运行在回放中掉了样本（IMU 最长断 0.73 s，相机最多 27 帧）。原因是我让 detect-a 与扫描并行跑，造成 CPU 争用。这 11 个运行在无其他负载下串行重跑，重跑后 70 个运行的输入审计全部零缺样。掉样本的运行和对应的 detect-a 输出保存在 `runs/imu-sweep/dropped/`，不参与本文任何数字。

- DET-SCALAR 在所有等级都能报警，但不能指出哪个轴（航向误归因 80–85%），不受陀螺等级影响。
- 真零偏预言机的航向漏报在所有等级都是 0%，说明航向冲突信号本身存在。DET-DIR 与它的差距来自零偏估计，g0 时差距最大，g4 时仍有 24%。
- **DET-DIR 的误报在所有等级都是 8–11%，超出 5% 目标的可比范围**，所以漏报数字偏乐观，不能和先导报告中的可比数字直接对比。但五个等级的误报水平相近，等级之间的趋势仍可读。

## 4 局限

- 每个等级只有一次噪声实现。g0 与原始仿真运行（同一噪声模型、不同实现）的航向最大误差，14 条中 13 条相差不到 1°，但雾 4 条纹横梁相差 3.9°（17.2° 对 13.3°）。所以单航次 1° 以内的差异不应解读，雾天航次的波动更大。
- T_tol 是解析值，不含初始零偏估计误差；平台上初始零偏误差可能占主导。
- 只替换了陀螺，加速度计和视觉不变；仿真视觉失效机制（条纹、雾）是否代表真实水下仍待平台数据。
- 检测阈值在 14 条航次上留一选取，同一批航次评分。

## 5 复现

```bash
bash scripts/imu_sweep.sh                       # 数据集、OpenVINS A0 1×、eval-traj；可续跑
.venv-eval/bin/python scripts/audit_input_trace.py --bag data/sim/<route>_<g>/ros2 --run $PWD/runs/sim_<route>_<g>_a0_r01
# detect-a：review_default.yaml 或 review_default_online_yaw.yaml 加一行 "health_target: 0.05"，--runs 为该等级 14 个运行
PYTHONPATH=team/uwbench .venv-eval/bin/python -m uwbench detect-a --config <cfg> --out runs/detect-a/imu_<g>_<frozen|online> --runs <14 runs>
.venv-eval/bin/python scripts/summarize_imu_sweep.py
```

不要在扫描进行时并行跑 detect-a 或其他重负载，否则 1× 回放会掉样本；每个运行都要核对输入审计零缺样。detect-a 会读数据集 bag 中的 `/imu0` 与 `/depth/pressure`，删除 `ros2/` 后需先用 `scripts/sim_to_bag.py --run <ds> --restore-bag` 恢复。
